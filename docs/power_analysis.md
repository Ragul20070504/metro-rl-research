# R-1 power analysis

Supplies the power analysis protocol section 8.4 leaves as `TBD@M11, frozen before the sweep`. Generated by `scripts/power_analysis.py` from the pilot; every number below comes from a stored result file.

## What the pilot was and was not

Pilot: `ppo_uq` vs `ppo_point` under `surge`, 4 training seeds x 10 evaluation seeds.

Pilot policies use training seeds 901-904 and evaluation seeds 41-50, both disjoint from the registered pools; the policies are discarded and no pilot observation enters a confirmatory result.

It was **not** used to tune hyperparameters, select a model, change reward weights, change scenarios, select seeds, or obtain significance.

## Power

| quantity | value |
|---|---:|
| pre-registered SESOI | 0.002 |
| alpha per confirmatory test (Holm) | 0.025 |
| target power | 80% |
| registered S (training seeds) | 10 |
| S required for the SESOI | 69 |
| S required for the observed effect | 5 |
| minimum detectable effect at registered S | 0.005909 |

**Decision: PROCEED with the registered n and report as potentially underpowered.**

detecting the SESOI would need S = 69, which is beyond the compute available. Protocol section 8.4's honest option is taken: run the registered design and state the minimum detectable effect in the paper. Lowering the SESOI is not an option.

## What this does not license

- The SESOI was frozen before the pilot and is not revisited. Protocol section 8.4: *"Lowering the SESOI after seeing the pilot is not an option."*
- A power calculation says what the design can detect; it says nothing about whether an effect exists. If the confirmatory test does not reject, the TOST equivalence test against this SESOI decides between *no evidence of benefit* and *evidence of no meaningful benefit*.
- The pilot's observed effect is an unbiased-but-noisy estimate from 4 seeds. It is used to report the required sample size, never as evidence about H1.
